# Хранилище броней — SQLite

_Реализация отложена: первый срез проекта — статичный лендинг без серверной логики. Решение вступает в силу, когда появится бронирование._

Брони должны переживать перезапуск процесса, а «проверка конфликта при бронировании» обязана быть честной, а не имитацией. Храним брони в SQLite через `better-sqlite3`, за интерфейсом-репозиторием; уникальность по началу слота обеспечивает «не более одной брони на слот» атомарно, без внешнего сервиса.

## Considered Options

- **In-memory** — проще всего, но данные теряются при рестарте и гонку нужно защищать руками.
- **JSON-файл** — переживает рестарт, но атомарность и конкурентный доступ решаются вручную.
- **Postgres** — лишний операционный и CI-сервис для учебного односервисного проекта.
